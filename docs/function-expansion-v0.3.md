# V0.3 功能扩展设计与实施计划

目标：把单流程报修原型扩展为可日常使用的单场地工单管理系统；保留已确定的报修、回执和权限设计。

## 方案选择

优先扩展现有工单数据：增加工单中心、状态看板、统计与汇总导出、居民筛选、服务说明及手动演示样例。相较于先做语音、多场地或自动派单，这组功能覆盖日常管理，并可在现有权限下验证。语音和多场地不进入本轮；不新增未经验证的自动维修判断。

## 行为与边界

- 工作人员页面路由：`/staff` 工作台；`/staff/tickets` 工单中心；`/staff/board` 看板；`/staff/analytics` 统计；`/staff/help` 服务说明。直接进入任一页面均要求工作人员登录。
- 工单组合筛选：关键词（忽略大小写及首尾空格，多个词同时匹配）、状态、类别、地点、归属、来源（手动提交/只读样例）、提交时间（全部/近7天/近30天）。支持最近更新、最新提交、最早提交排序；不改变工单状态。
- 看板按6个现有状态分列，仅导航查看详情；不通过拖动绕过状态、版本和负责人校验。
- 统计为当前筛选记录的数量快照，展示总量、进行中、待居民回应、已关闭、已撤回、样例数，以及状态/类别/地点分布和近14个北京时间日期的新增量。禁止把当前关闭数命名为维修质量、修复率或用户收益。
- 汇总导出仅供本场地工作人员使用，含筛选范围、分类数量与趋势；不导出自由文本、身份、照片、会话或模型原文。表格字段处理公式注入。
- 只读样例由工作人员在演示空间手动载入；固定12条、重复请求不追加。使用显式 `isExample=true` 标识并与手动报修区分；不自动载入、不覆盖已有数据、不创建真实用户身份或照片。试点空间拒绝载入。样例不能认领、修改、提交回执或触发模型；用于查看不同阶段，实际操作通过新建报修体验。
- 居民只筛选自己的报修，提供全部/需回应/进行中/已结束及关键词搜索，不扩大访问范围。
- 服务说明展示配置状态与操作步骤；“已配置”不等于已验证模型可用，不显示密钥或内部接口细节。
